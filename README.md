- [开源维护手册](docs/PLAYBOOK.md)：从新项目到日常维护。

- [贡献指南](CONTRIBUTING.md) · [安全政策](SECURITY.md)。
- [个人主页](https://github.com/shanghe000)。

## 如何生效

GitHub 会在符合条件且缺少对应文件的仓库中使用这里的默认社区文件；已有仓库自己的文件优先。
Issue 表单位于 `.github/ISSUE_TEMPLATE/`。如果目标仓库已有自己的 Issue 模板目录，则应在目标仓库中维护模板。

工作流、Dependabot、许可证、分支规则和仓库设置**不会**通过此仓库自动继承。
新项目请使用模板并完成初始化；现有项目逐个接入。

## 每周维护清单

`Repository audit` 每周一 09:20（北京时间）扫描本账号的公开原创仓库，生成可下载的 Markdown 清单和 Actions 摘要。
内容包括简介、主题、许可证、README、工作流、未结事项与最近更新时间；不自动创建 Issue 或修改仓库。
可在 [Actions](https://github.com/shanghe000/.github/actions) 中手动运行。

实现与继承规则参见 [GitHub 官方说明](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/creating-a-default-community-health-file)。
